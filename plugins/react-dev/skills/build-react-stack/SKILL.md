# Build React Stack

Build a client-rendered React SPA as a dependent layer on the Go application foundation. The Go binary serves the API, MCP and the built UI from one origin.

## Apply the required Go foundation

1. Read and apply the `build-go-stack` skill in full (the react-dev plugin's `agentpack.toml` pins it) before planning or changing the frontend. This dependency is mandatory even for frontend-only tasks because API contracts, actors, configuration, verification order, and artifact ownership cross the boundary.
2. Keep `build-go-stack` authoritative for Go packages, backend APIs, configuration, logging, errors, MCP, and backend tests.
3. Keep this skill authoritative for `ui/`, browser behavior, client routing, and the frontend-to-Go integration seam (proxy, staging, embedding, SPA fallback).
4. Resolve overlap by dependency direction: this skill may constrain how the frontend consumes or is staged into Go; it must not redefine backend architecture.

## Use the stack

- **Vite** (current major, Rolldown) with `@vitejs/plugin-react`, **React** (current major) with **React Compiler**, **TypeScript 7** (native `tsc`) in strict mode.
- **TanStack Router** with file-based routes generated by `@tanstack/router-plugin/vite`; typed path params, validated search params, route loaders.
- **TanStack Query** (v5) for all data owned by the Go API.
- **Tailwind CSS** (current major, `@tailwindcss/vite`) and **shadcn/ui**.
- **Bun** for install, scripts, and package execution; **Vitest** for tests; **Oxlint** for lint.
- **vite-plugin-pwa** only when the product asks for an installable or offline-start app.

There is no client state library: URL, Query cache, and React state cover every case (see [references/state.md](references/state.md)).

Verify current majors with `bun pm view <pkg> version` before scaffolding or upgrading, read the official docs for any API you are about to use, and pin exact versions through `bun.lock`. Do not copy version numbers from memory or from this skill. Next.js, Remix/React Router framework mode, RSC, server actions, and static-export tooling are out of scope; do not add them.

## Start with frontend discovery

1. Inspect repository instructions, `ui/package.json`, `bun.lock`, `vite.config.ts`, `tsconfig*.json`, `components.json`, `src/routes/`, frontend build targets, API contracts, and existing conventions.
2. Preserve compatible choices and avoid unrelated visual or package churn.
3. Read [references/frontend-integration.md](references/frontend-integration.md) before changing the API client, query keys, auth, public configuration, the dev proxy, build output, staging, Go embedding, SPA fallback, or cache headers.
4. Read [references/state.md](references/state.md) before adding state: search params, query cache, or component state.
5. Read [references/shadcn-ui.md](references/shadcn-ui.md) and apply the **shadcn** skill before changing components, forms, dialogs, navigation, or shared visual patterns.
6. Read [references/performance.md](references/performance.md) before changing Bun/Vite scripts, React Compiler, UI checks, the size budget, staging, fingerprints, caches, or the combined artifact pipeline, and before adding any dependency over 20 KB gzipped.
7. Read [references/pwa.md](references/pwa.md) before adding a manifest-driven install, service worker, or offline behavior.
8. Apply **impeccable** for a new or substantially reshaped visual direction, plus the product-specific UI skill when one exists.

## Use the frontend layout

```text
ui/
  index.html
  src/
    main.tsx              # QueryClient, router, providers, render
    router.tsx            # createRouter + Register declaration
    routeTree.gen.ts      # generated; never hand-edit
    routes/
      __root.tsx          # createRootRouteWithContext, shell, error/not-found
      index.tsx
      w.$workspace.tsx    # workspace layout route (auth + reconciliation)
      w.$workspace.issues.index.tsx
      w.$workspace.issues.$issueId.tsx
    features/<feature>/   # queries.ts, components
    components/
      ui/                 # shadcn CLI-managed primitives
    lib/                  # api client, utils (cn)
  scripts/
    check-size.ts         # gzip budget gate, runs after vite build
    index.css             # Tailwind import + theme tokens
  public/                 # unhashed root files: favicon, manifest, robots
  components.json
  vite.config.ts
  tsconfig.json
  package.json
  bun.lock
```

- Manage the frontend with Bun: `bun install`, `bun run`, `bunx --bun`. Commit `bun.lock`; do not introduce npm, pnpm, or yarn lockfiles.
- Register `tanstackRouter({ target: "react", autoCodeSplitting: true })` before `react()` in `vite.config.ts`. Commit or regenerate `routeTree.gen.ts` consistently with repository practice; never edit it.
- Pass `queryClient` through router context (`createRootRouteWithContext<{ queryClient: QueryClient }>()`) and declare `Register` once so `Link`, `useNavigate`, `useSearch`, and `useParams` are typed.
- Set `base: "/"` and keep the default `ui/dist` output with hashed files under `dist/assets/`. A relative base breaks asset URLs on deep links.

## Route, load, and render

- Model identity in the path: `/w/$workspace/issues/$issueId`. Real dynamic segments are the reason this stack exists; do not encode entity identity in query strings.
- Model shareable view state (filters, sort, tab, page, selection, view mode) as typed search params with `validateSearch`. Use `.catch()` fallbacks so malformed URLs degrade instead of erroring.
- Load route data in `loader` with `context.queryClient.query({ ...opts, staleTime: "static" })` (the replacement for the deprecated `ensureQueryData`); render with `useSuspenseQuery(opts)` from the same `queryOptions` factory. Use `loaderDeps` to pass only the search params the loader reads.
- Start independent loads together with `Promise.all`; prefetch non-critical data without awaiting it. Set `defaultPreload: "intent"` and `defaultPreloadStaleTime: 0` so Query, not the router, decides freshness.
- Use `beforeLoad` in layout routes for auth and workspace reconciliation; `throw redirect(...)` to login with the return location in search.
- Give the root and every layout route an `errorComponent` and `notFoundComponent`; use `pendingComponent` for slow loaders. Reset Query error boundaries in the error component and retry with `router.invalidate()`.
- Rely on `autoCodeSplitting` for route components. Lazy-load genuinely heavy optional UI inside a route with `React.lazy` + `Suspense`.

## Write modern React

- Function components and hooks only; no class components. Use the router's route-level error boundaries instead of hand-written ones, and Suspense boundaries at routes rather than scattered spinners.
- Derive render values during render; do not mirror props, query data, or search params into state through effects. Put interaction logic in event handlers. React Compiler memoizes; do not hand-write `useMemo`, `useCallback`, or `memo` without a profile showing a compiler bailout.
- Prefer composition over boolean props: explicit variants, compound components, `children` and slots. Keep providers to the fixed set in `main.tsx` (Query, router, tooltip/toaster); do not build feature context stacks.
- Import modules directly instead of through broad barrels.
- Keep form state local; submit through `useMutation` and update or invalidate exact query keys.

## Build UI with shadcn/ui

- Use the repository's existing shadcn preset, or `base-nova` when initializing a new project with the Vite template.
- Run the package-runner form of `shadcn info` before assuming the base, aliases, icon library, or installed components; read `shadcn docs <component>` before implementing an API from memory.
- Keep CLI-managed primitives in `src/components/ui/` and composition in feature directories. Use semantic theme tokens. Self-host fonts through packages or files imported in CSS so Vite hashes them.
- Give primary entities dedicated shareable routes. Reserve dialogs, sheets, and drawers for bounded transient work; when an overlay must be linkable, open it from a search param.
- Scope global shortcuts away from form controls and editable content. Validate keyboard focus, reduced motion, and mobile behavior.

## Keep the browser same-origin

- Call relative routes such as `/api/issues` and `/api/config`; never construct or configure an API origin.
- In development, proxy `/api` (and `/mcp` when the UI uses it) from Vite's `server.proxy` to the fixed local Go origin. Do not rewrite the path.
- Do not use `import.meta.env` / `VITE_*` variables, runtime config files, injected globals, or build-time substitution for application configuration. Load the typed public document from Go `GET /api/config` in the root route loader.
- Do not add production CORS for the same-origin deployment.

## Embed one artifact and own the fallback

1. Build with `vite build` into `ui/dist`, verify it, and stage it beneath the Go module in a generated directory suitable for `//go:embed all:dist`. Never embed across module boundaries.
2. Register API, health, metrics, and MCP routes before any frontend handler.
3. Serve `/assets/*` from the embed with long immutable caching; a missing asset returns `404`.
4. Serve known root files from `public/` with short caching.
5. Serve `index.html` with `Cache-Control: no-cache` for every other `GET`/`HEAD` path that is not under `/api`, `/mcp`, or another reserved backend prefix and whose last segment has no file extension. Unknown `/api/*` paths return the API's JSON `404`, never HTML.
6. Fail the complete artifact build when `dist` is missing or stale. Never silently ship an empty or outdated UI.

Centralize UI build, verification, staging, and final artifact commands in the repository's existing build tool. Keep backend-only, UI-only, fast-check, and complete-artifact targets distinct. The normal Go edit loop must not rebuild the UI.

## Verify proportionally

- Follow repository validation order: Oxlint first, `tsc --noEmit` when types, routes, or contracts changed, focused Vitest + Testing Library only for high-risk interaction state, then `vite build`, the size budget, and staging when frontend inputs changed.
- When the integration seam changes, smoke-test through the built Go binary: `/` and a deep link such as `/w/acme/issues/42?tab=activity` return `index.html` (deep-link refresh), a hashed JS and CSS asset return with the right content type and immutable caching, a missing `/assets/x.js` returns `404`, `/api/nope` returns the JSON `404`, `/api/config` works, and `/mcp` is not shadowed.
- Use targeted browser inspection only when static checks cannot falsify behavior. Keep scripted Playwright for the final regression gate or changes to its coverage.
- Preserve the Bun cache and Vite's `node_modules/.vite`; install worktree-local dependencies and never symlink `node_modules` outside the worktree.
- Report commands, timing, failures, assumptions, and skipped checks.

## Reject recurring failure modes

- Do not add Next.js, `app/` or `pages/` directories, `next.config`, static export, RSC, or server actions.
- Do not work around routing with query-string identity or hash routing; use path params and the Go history fallback.
- Do not let the SPA fallback answer `/api/*`, `/mcp`, or missing assets with `index.html`.
- Do not cache `index.html` long-term or serve hashed assets without immutable caching.
- Do not use a relative Vite `base`; deep links will load assets from the wrong path.
- Do not copy query results into `useState` or context, or duplicate Query loading and error state.
- Do not keep shareable view state in component state when it belongs in search params.
- Do not add Jotai, Zustand, Redux, or a global store, and do not wrap every feature in its own React context.
- Do not raise a size budget to make a build pass; split the chunk or drop the dependency.
- Do not hand-write a service worker or let it answer `/api`, `/mcp`, or OAuth paths.
- Do not hand-write `routeTree.gen.ts`, untyped `navigate({ to: string })` paths, or unvalidated `URLSearchParams` parsing.
- Do not add an API base URL, `VITE_*` application configuration, or production CORS.
- Do not hand-roll common UI controls when an installed shadcn primitive or composition fits, or make overlays the canonical detail view for primary entities.
- Do not use `bun test` in place of Vitest; Bun runs the scripts, Vitest runs the tests.
- Do not make backend-only checks rebuild an unchanged frontend or replace staged files whose contents are unchanged.
- Do not alter Go architecture here; apply `build-go-stack` for backend changes.
