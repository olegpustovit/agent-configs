# shadcn/ui in the React stack

Use **shadcn/ui** as the default component system for `ui/`. Components are copied into the repository as source under `src/components/ui/` and composed into feature components and routes.

## When to read this

Before adding UI surfaces, forms, dialogs, navigation shells, command palettes, tables, or shared visual patterns in `ui/`.

Also follow the **shadcn** skill for CLI commands, composition rules, styling constraints, and component selection.

## Project conventions

- Initialize a new project with the Vite template: `bunx --bun shadcn@latest init -t vite` inside `ui/` (or the command generated by the shadcn create page). Commit `components.json`. `rsc` must be `false`.
- Set the `@/*` alias in `tsconfig.json` `paths` (`"@/*": ["./src/*"]`) and in `vite.config.ts` `resolve.alias`. Do not add `baseUrl`; current TypeScript deprecates it and `paths` resolves relative to the tsconfig.
- Run `bunx --bun shadcn@latest info` before assuming aliases, component base, icon library, Tailwind version, or installed components. Run `docs <component>` before implementing against a component API from memory.
- Add components with `bunx --bun shadcn@latest add <name>`. Prefer composing existing components before writing custom markup.
- Preview updates to installed components with `--dry-run` and `--diff`; never overwrite local component changes without explicit approval.
- Keep aliases from `components.json` (`@/components/ui`, `@/lib/utils`). Do not hardcode alternate import paths.
- Theme tokens live in `src/index.css` (`@import "tailwindcss";` plus the shadcn variables). Edit that file; do not create parallel theme files.
- Self-host fonts with a font package (for example `@fontsource-variable/geist`) imported in `main.tsx` or CSS, so Vite hashes the `woff2` files into `dist/assets/`. Map the Tailwind token to the font family, never to itself:

```css
@theme inline {
  --font-sans: "Geist Variable", ui-sans-serif, system-ui, sans-serif;
  --font-mono: "Geist Mono Variable", ui-monospace, monospace;
}
```

Never write `--font-sans: var(--font-sans)`; the circular reference breaks `font-sans` and falls back to browser serif defaults. Do not load fonts from a third-party CDN.
- Use semantic Tailwind tokens (`bg-background`, `text-muted-foreground`, `border-border`). Do not override component colors with raw palette classes.
- Use `FieldGroup` + `Field` for forms, `Sidebar` for app navigation, `Command` inside `Dialog` for command palettes, `Table` + `Badge` + `Avatar` for entity lists, and `Dialog`/`Sheet` for modals.
- Keep items inside required groups, give every dialog/sheet/drawer a title, include `AvatarFallback`, and use the base-specific `asChild` or `render` trigger API reported by `info`.
- Mount required providers once in `main.tsx` (`TooltipProvider`, `Toaster`).

## Routing is product UI

- Primary entity details belong on full routes with stable, shareable URLs and browser navigation (`/w/$workspace/issues/$issueId`). Use a wide content column plus a stable metadata/action rail when a record combines narrative content, activity, and properties.
- Dialogs and sheets are for bounded transient work. When one must be linkable (create form, quick preview), drive `open` from a typed search param and close by navigating; otherwise keep `open` in local state.
- Navigation uses the router's typed `Link`. For shadcn components that render a link, pass `Link` through the trigger API (`asChild` or `render`) so active state, preloading, and type checking keep working; do not use raw `<a href>` for internal routes.
- Use `Link`'s `activeProps` / `data-status="active"` for sidebar and tab active styling instead of comparing pathnames by hand.

## Layout shape

```text
ui/src/
  main.tsx              # providers
  index.css             # Tailwind + shadcn theme tokens
  components/ui/        # shadcn primitives (CLI-managed)
  features/<feature>/   # feature composition (hand-written)
  routes/               # route files compose features
  lib/utils.ts          # cn()
```

Keep shadcn primitives in `components/ui/` and compose upward into features; route files stay thin.

## Build output

Vite emits CSS, fonts, and images into `dist/assets/` with content hashes, and copies `public/` to the `dist` root. The Go stage step must copy the whole `dist/` tree; verify that every stylesheet and `url(...)` reference resolves before embedding (see [performance.md](performance.md)).

## CLI quick reference

```bash
cd ui
bunx --bun shadcn@latest info
bunx --bun shadcn@latest search @shadcn -q "sidebar"
bunx --bun shadcn@latest add button dialog sidebar command
bunx --bun shadcn@latest docs button dialog
```

## Do not

- Hand-roll styled divs when an installed shadcn component fits.
- Use `space-x-*` / `space-y-*` for layout; use `flex` + `gap-*`.
- Add npm/pnpm/yarn shadcn invocations in docs or scripts for this stack; use Bun.
- Edit generated shadcn component files for one-off styling when a variant or composition change is enough.
- Add `"use client"` directives or Next-specific imports (`next/link`, `next/font`, `next/image`); they have no place in this SPA.
